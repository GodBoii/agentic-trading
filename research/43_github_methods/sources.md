# Source review

Reviewed 2026-10-09. Exact commit, raw URL, byte count and SHA256 for every file appear in `upstream/manifest.json`. Saved files are inert `.txt` evidence with upstream notices preserved. No repository was installed or executed. These are narrow source inspections, not audits of entire projects. A repository's existence or popularity is not evidence of profitable prediction.

| Repository and inspected source | Formula or method found in source | Local decision |
|---|---|---|
| [Microsoft Qlib Alpha158 loader](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/qlib/contrib/data/loader.py) | Builds candle and rolling price/volume factors. Examples include `KMID=(close-open)/open`, `RSV=(close-min(low,n))/(max(high,n)-min(low,n)+epsilon)`, `SUMP=sum(max(delta close,0))/sum(abs(delta close))`, and price/log-volume correlation. These are input factors, not an accuracy formula. | Useful candidate feature bank. Existing project already tests related momentum, RSI, range and volume ideas. No Alpha158 model was trained here. Original defaults are daily windows, so applying them to minute quotes would be an adaptation. |
| [QuantConnect LEAN KAMA](https://github.com/QuantConnect/Lean/blob/80e7843f645673bcbeaab963049f76f20f6785e1/Indicators/KaufmanAdaptiveMovingAverage.cs) | An efficiency ratio from the parent indicator adjusts `alpha=[ER*(2/(fast+1)-2/(slow+1))+2/(slow+1)]^2`; update `KAMA=KAMA_prev+alpha*(price-KAMA_prev)`. Source defaults use fast 2 and slow 30. | Adaptive trend smoothing is a plausible future comparator. No KAMA backtest ran in this track. The inspected file delegates the exact ER calculation to a parent class, which was not inspected here. |
| [mlfinpy symmetric CUSUM](https://github.com/baobach/mlfinpy/blob/89511cc1ee4695beed0044bbbc6665d98ac4a5c5/mlfinpy/filters/filters.py) | Uses log returns with one positive and one negative cumulative statistic, strict threshold crossings, negative crossing priority, and reset of only the triggered side. The function returns event timestamps. | Reimplemented the same recursion in forward state, in bps, with a fixed 15 bps threshold. Added signed direction and explicit quote/history resets. Turning an event into a continuation trade is our hypothesis, not a source claim of predictive edge. |
| [pykalman forward recursion](https://github.com/pykalman/pykalman/blob/d62e60be00bd028ecc7eea6a8bea02f583910428/pykalman/standard.py) | `_filter_predict` uses `m_pred=F m`, `P_pred=F P F.T+Q`; `_filter_correct` uses `K=P_pred H.T/(H P_pred H.T+R)`, `m=m_pred+K*(y-H m_pred)`, followed by covariance correction. | Implemented a two-state local-linear log-price/slope model with fixed parameters and Joseph covariance update. The source is a general filtering library, not a trading strategy. Trading thresholds, covariance assumptions and the AND combination are ours. No EM, future smoother or pykalman code ran. |
| [FinRL stock environment](https://github.com/AI4Finance-Foundation/FinRL/blob/85b24fd7b0db6fc9beb24c3690b897e50922564c/finrl/meta/env_stock_trading/env_stocktrading.py) | States include cash, asset prices, positions and indicators. Continuous actions become integer share quantities, buys/sells deduct configured percentage costs, and reward is `reward_scaling*(end_total_asset-begin_total_asset)`. A turbulence threshold can force liquidation. | RL optimizes a trading reward, not automatically a calibrated price prediction. This inspected file contains the environment, not a specific learned agent. Seven dependent historical sessions do not provide credible broad RL validation. No RL training ran. |
| [skforecast recursive forecaster](https://github.com/skforecast/skforecast/blob/8a8019ae0482b9f25f4a364025b6d11c5196cc45/skforecast/recursive/_forecaster_recursive.py) | Fits a configurable estimator using lag features, optional window/exogenous/calendar features. `_recursive_predict` feeds each predicted value back into the next lag window. Thus `yhat_(t+h)=f(lagged actual/predicted y, known x)` and errors may propagate across horizons. | Useful general forecasting workflow, not a stock-specific alpha. A price-level accuracy score can favor persistence while providing no return edge. No skforecast estimator was trained here. Future use needs chronological fitting, known-at-decision exogenous data and return/cost benchmarks. |
| [mlfinlab current public CUSUM file](https://github.com/hudson-and-thames/mlfinlab/blob/79dcc7120ec84110578f75b025a75850eb72fc73/mlfinlab/filters/filters.py) | Both `cusum_filter` and `z_score_filter` contain docstrings followed by `pass`. The current public file inspected here does not provide executable filter logic. | Did not treat this stub as working code or evidence of tested implementation. Used the separate mlfinpy implementation above for the actual CUSUM recursion. |
