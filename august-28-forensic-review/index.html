What is actually wrong in the chart path

The stock agent fetches Dhan history, then merge_recent_bars replaces every overlapping timestamp with Intra Finder's live aggregate. The two feeds have different open/high/low/volume values in some minutes. The first live bar after gateway startup can also carry zero incremental volume. Price closes are generally close, but derived VWAP, ATR, volume impulse, candle patterns, and support levels can move.

Recommended implementation order

Fix the controls before changing the model

  1. P0

    Expire unfilled entry legs

    Cancel pending limits after one completed 1m bar or a strict 2–3 minute TTL. Re-run freshness, direction, and risk checks before any later fill.

  2. P0

    Persist the complete super-order lifecycle

    Store entry, target, stop, trigger, update, and exchange timestamps before day rollover. Alert when the realized exit differs from the requested protection geometry.

  3. P1

    Gate extension and opposing evidence

    Reject entries that drift more than 0.25 ATR from the event reference. Do not short when 5m RSI is deeply oversold or buy when an opposing engulfing candle is still active without a fresh confirmation.

  4. P1

    Separate completed bars from developing bars

    Supply completed 5m and 15m indicators as the decision contract. Keep the live 1m chart for execution timing, not setup confirmation.

  5. P1

    Reconcile live bars instead of overwriting history

    Use finalized broker bars through the last closed minute. Append only the current developing minute from the feed and log differences above a tick-aware tolerance.

  6. P2

    Reduce evidence that is not decision-bound

    TPO, market profile, and OHLCV “liquidity” charts are cited inconsistently. Keep them only if a named rule consumes them; otherwise they add visual load without a measurable gate.
